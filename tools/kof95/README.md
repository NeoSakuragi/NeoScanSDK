# KOF95 animation dictionary

Data (exports, gallery pages, MAME save states, capture recordings): `/data/neogeo_dict/` (see its README.md);
the `capture/` recording folders here are symlinks into it.

Everything the brawler prototype (`examples/brawler`) takes from The King of Fighters '95, decoded from the ROM and
checked against the running game in MAME. The gallery artifact plays all of it:
https://claude.ai/artifact/GWfkQjLW2KAQjXzux6nznN (generated by `gallery.py`).

ROM: `/data/roms/kof95.neo` (`rom.py` byte-swaps P to CPU order). MAME: `mame kof95 -rompath ~/Downloads`, save states
in `~/.mame/sta/kof95/` (`a` = Terry vs Terry, `0` = Kyo vs Kyo, `2` = Ryo vs Ryo, `3` = Ryo vs Robert).

## The cast

Character id = index into every per-character table. Ids 0–25 are the fighters: Heidern, Ralf, Clark, Athena, Kensou,
Chin, Kyo, Benimaru, Goro, Iori, Eiji, Billy, Kim, Chang, Choi, Terry, Andy, Joe, Ryo, Robert, Takuma, Yuri, Mai, King,
Saisyu, Omega Rugal (there is no first-form Rugal fighter). Ids 26–29 are effect tables (projectiles, sparks, debris).

## Per-character data

| What | Where | Notes |
|---|---|---|
| state table (animation slots) | `$080000 + id*4` → 256 longs | slot → animation bytecode |
| sprite definitions | `$080080 + id*4` | |
| state → slot map | `$57D0A + id*2` (remap) → `$7C948 + n*4` → 2 bytes per game state | second byte = normal play |
| palettes | `$1D9000 + id*$400` | 16 palettes; `+$200` = mirror-match set; colour 0 = tag `$100+id*$20` |
| 128-byte record | `$7AEF2 + id*128` | +0: 8 command ids; +$24 walk, +$28 jump launch, +$2C gravity (16.16) |

Walk back = ¾ walk; jump drift = walk (measured in MAME, matches the record exactly for Terry, Kyo, Ryo, Robert).

### Animation bytecode
6-byte steps `[ticks][frame record:24][flags:16]`. Control bytes (dispatch at `$3CE4`): `$FF` loop, `$FE` hold,
`$FD TT x y w h` box (TT>>4: 1 attack, live only on the next step; 3/4 hurtboxes, persist), `$FB` x move (signed by
facing), `$FA` spawn an effect object (code table `$36964`), `$FC` a disabled sound call. Step flag byte 5 → object `+$7D`;
bit 0 = event (projectile spawn frame, throw look-ahead). Boxes are centre + half extents from the feet.

### Frames and sprites
Frame record = chain of parts `[dx][dy][word]`: word bits 0–8 sprite definition, 13 = another part follows, 14/15 =
H/V flip. Sprite definition: `[cols][rows][palette slot][tile bits 16-19 | …][tile:16]` + one bitmask per column;
**byte 2 is the hardware palette slot**: `$10` = the owner's body (relocated per player and team position: 16–111 are
the fighters' blocks), anything else a fixed effect palette at `$1D7000 + slot*32` (e.g. Power Wave `$8E`). ROM sprites
face **left**.

## Shared slots (same for every fighter)

| Slots | What |
|---|---|
| 0–23 | idle, walk, jumps (rise/fall per direction), crouch, turn, guard |
| 34 / 35 | C+D "body toss", ground / air (game states 96 / 111) |
| 54–81 | hits (54 light, 60 heavy, 61/62 crouch), 65 air hit, 66 blowback, 67 trip, 74 knockdown fall, 78 down, 80 get-up, 81 dizzy |
| 82–101 | normals: 5 per button A–D — close, far, jump, jump diagonal, crouch |
| 102–255 | the character's own moves (specials, throws, supers, intros) |

Knockdown physics (measured on Terry): gravity 0.46875; air hit vy 6.5 vx 2.5; trip vy 8.0 vx 2.0; blowback vy 5.25
vx 3.5, bounce vy 4.0; get-up 25 frames.

## Special moves

**Inputs — command recogniser at `$B2C0`** (`commands.py`). The 8 command ids of the character (record +0, copied to
object `+$E8`) each point to a motion pattern (`$7A6B0 + (id-1)*4`): 4-byte steps `[type][input][mask][frames]`, `$FF`
ends. Stick bits 1 up 2 down 4 back 8 forward (mirrored for a fighter facing left); buttons A `$10` B `$20` C `$40`
D `$80`; C folds onto A and D onto B unless type bit 7 is set (so A = punch, B = kick); type bit 0 = charge (hold
`frames`). A match sets bit k of the player's command byte (`$10D7C0` for P1, input block `$10D7BC`); the dispatcher
(`$7740`) runs entry k of the character's move table (`$77DE[id]`). Condition per command (`$B388`, routines at `$B4A0`):
airborne, mash, super (power `+$118` = 127 or life `+$120` ≤ 64), etc. 152 of 153 decoded commands produced their move
in MAME (Joe's 236P did not come out).

**Moves are 68000 code**, one routine per game state: it sets the state (animation via the map), velocities (`+$50`),
sounds (`$6342`), and spawns objects with `$49B6`/`$49BA` at the frame flagged in the animation. A projectile is a pool
object (`$100100 + n*$200`, owner at `+$84`) using an effect table (`+$70`, e.g. 26); its state is its slot. Spawn
offsets and speeds are immediates in its routine (Power Wave: +40 px, 4 or 7 px/frame), so they come from capture
(`capture/specials.py`, per-frame replay scripts incl. projectiles).

## Throws

**Victim placement — routine `$4AE6`** (byte tables) and `$4BF4` (word tables), called every frame of a throw with a
table of 26 lists, one per **victim** id. Entry = thrower's animation step count (`+$82`) − 1:
`[victim state, dx (negated), dy, flags]` (bit 6 = victim drawn in front; non-zero = release). The victim's own
state → slot map gives its frame, so each body has its own drawing **and** its own offset per throw step.
Rules (`throwtables.py`, `predict`): look-ahead to the next entry when the thrower's step has the event flag; nothing
moves during the thrower's hit-stop (`+$7B`); afterwards every fighter is clamped to camera (`$10B078`, last frame's
value) +32 … +288 (`$3B500`). Multi-table throws (Goro, Omega Rugal) use one table per thrower phase; hold throws (Chin,
Choi) begin with a short approach outside the table. Kensou's throw is a strike (victim plays its own fall).
Tables per throw: `throw_tables.json`.

**Validation**: all 26 mirror-match throws reproduce frame for frame up to the release frame (where the release
velocity is added), and Heidern's throw on 6 different victims matches 42/42 frames each.
`throwscripts.py` builds every thrower × every victim (26 × 26) for the export and the gallery's victim selector.

**Portable poses**: `victim_poses.json` names each of the 77 victim states a table can use with a posture (grabbed,
bent_back, hunched, hit_reel, launched, horizontal, falling, inverted, inverted_diagonal, lying) and an approximate
angle, so throws can drive sprites from other games.

## MAME capture technique (`capture/`)

Always pass `-noplugin cart_bridge`: the system-wide `cart_bridge` plugin is an old NeoCart test stub that exits MAME at
screen frame 3400 (the count is restored from save states). The capture scripts do.

- `record.lua`: scripted inputs for both players (`SEQ`/`SEQ2`, `frames:inputs`), RAM pokes (`POKE`), screenshots
  (`SNAPS`, under `xvfb-run -window`), camera log (`CAM_OUT`); dumps both fighter objects ($200 bytes) every frame.
  `record_spawn.lua` adds P1-owned pool objects; `statetap.lua` / `pctap.lua` log writes / reads with the PC (and A0).
- **Any fighter in a match**: set P1's team record `$10A843–$10A845` (P2: `$10A853–55`) to the id and P1's health
  (`$108220`, `$108222`, `$10824C`) to 1; after P2's hit the next round loads that fighter for real (both sides when
  both records are set). Poking only the object's id byte (+$71) gives the graphics with the wrong moves.
- Round timer `$10A836` (BCD, max 60), P2 health `$108420`, power gauge `+$118` (127 = full).
- The game reads input a few frames late: press the button together with the last direction and hold it.
- Object layout: `+$18` x, `+$20` height, `+$28` frame record, `+$31` bit 0 facing (1 = right), `+$3C` sprite-def
  table, `+$70` table id, `+$72` game state, `+$74` raw step offset, `+$7B` hit-stop, `+$7D` step flags, `+$82` steps
  played, `+$84` owner, `+$B6` opponent, `+$120` health, `+$182` id×4.
